## How the project builds and runs

It was mostly documented in the README. The README left out one step and the dependencies, and I have added both.

- **What it is.** A static site in `docs/`: plain ES modules, a vendored `d3.min.js` (v7.9.0, the current
  release) and one data file, `docs/data/archive.json`. There is no bundler, no `package.json` and no CI.
  GitHub Pages serves `docs/` (https://qav2.github.io/star-wars-timeline/).
- **Dependencies.** Python 3 with `requests`, and Pillow for portraits. There was no requirements file. I added
  `tools/requirements.txt`.
- **Pipeline.** Every step reads Wookieepedia through `tools/wp.py`, which caches pages in `cache/wp/`.
  `cache/` and `build/` are gitignored, so a fresh clone refetches everything.
  1. `tools/fetch_records.py`: the canon and Legends media timelines plus every film and episode page, into `cache/wp/`.
  2. `tools/parse_records.py`: writes `build/records.json`.
  3. `tools/places.py`: writes `build/places.json`.
  4. `tools/routes.py`: writes `build/routes.json`. **This step was missing from the README.** `build.py` reads its
     output, and without it the star map has no hyperspace lanes. (`build.py` falls back to an empty list, so it
     does not error.)
  5. `tools/build.py`: merges the above with `data/curated/*` and writes `docs/data/archive.json`.
  6. `tools/fetch_portraits.py resolve` and then `download`: crops images into `docs/img/p/` and writes
     `data/portraits.json`. This step reads `archive.json`, and `build.py` reads `portraits.json`, so run
     `build.py` again afterwards. I added that to the README.
- **Run it.** `python3 -m http.server -d docs`. Add `?dbg`, `?legends=1` or `?skin=<id>` to the URL.
- **Check it.** New: `python3 tools/smoke_test.py [--browser]`. See below.

### Smoke test

`tools/smoke_test.py` uses only the standard library by default. It checks that `archive.json` parses, that each
collection has at least a minimum count (for example 600 records and 1,000 people), that record ids are unique,
that every record has a lane and a time, that every portrait file exists, that every skin has `skin.css` and
`skin.js`, and that every local reference in `index.html` and the CSS resolves. With `--browser` it serves
`docs/` on a free port, opens all four skins with the Legends layer on, clicks through every section, and fails
on any console error, uncaught exception, failed request, 4xx/5xx response, gate that never opens, or missing
section counts. `--browser` needs `pip install playwright`. Set `CHROMIUM=/path/to/chrome` to use a browser other
than Playwright's own.

## Left for Joe

- **Major version bumps: none.** There is nothing to bump. The Python dependencies are unpinned, and d3 is at the
  latest release.
- **A rebuild today would lose two loglines and change two record ids.** On Wookieepedia, the infobox for the
  Forces of Destiny short "Newest Recruit" now says `episode: 12`, while its own lead still says it is the ninth.
  `parse_records.py` then sees two `fod-1x12` records and renames both to `fod-1x12-newest-recruit` and
  `fod-1x12-the-starfighter-stunt`. That drops their curated loglines, which are keyed `fod-1x09` and `fod-1x12`
  (656 own loglines instead of 658), and breaks any `#/x/fod-1x09` link. There are two ways to fix it: correct
  the Wookieepedia infobox, or add an id override in `parse_records.py`. I left it alone because it is a data
  call.
- **Other drift in a rebuild.** Compared with the committed file, a rebuild changes cast lists on 298 records,
  the in-universe position (`t`) of 148 records, the remote cast on 25, the flashback cast on 8, and the date text
  on 3. It also adds 2 people, and one more place gets a grid square (417 instead of 416). The site still works with it, and the smoke test passes. Refresh it
  when you want to.
- **85 portraits are fetched but never shown.** `data/portraits.json` has portraits for 85 figures who appear
  only in the curated overlays (lineages, visions, relics), for example Avar Kriss, Cal Kestis and Cere Junda.
  `build.py` attaches portraits only to people who appear in screen records. The app creates a bare entry for
  overlay-only figures, with no portrait. As a result, 80 image files in `docs/img/p/` are committed but
  unreferenced. Commit `8484923` says "portraits for lineage and relic figures", so this looks unintended. A
  fix would mean `build.py` emitting those people (with `n: 0`) or a separate portrait map. I didn't make the
  change, because it means shipping a rebuilt `archive.json`, which brings in the drift above.
- **`build/principals-1.json` has no generator.** `research/briefs/personnel.md` names it as the input for
  dossier passes, but no script in `tools/` writes it. It probably came from a one-off command. I only need to
  know about it if more personnel passes are planned.
- **No CI.** The smoke test could run in a GitHub Actions workflow on push. I didn't add one, because the brief
  rules out anything that ships and a workflow is new infrastructure. It's a small follow-up if you want it.
- **The Gordian Reach route** resolves to 0 waypoints on Wookieepedia, and the Kessel Run and Sisar Run have
  fewer than 3 gridded points, so the star map draws 8 of 12 listed lanes. This is upstream data. The code
  handles it.
- **Branch naming.** The repo's default branch is `master`, not `main`, so the PR targets `master`.
